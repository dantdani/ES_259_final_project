major phase of the project:

  2. Model architecture evolution (v1 → v2 → v3 seed-conditioned ResMLP).
  3. Data-scaling sweep with the stable v3 architecture (10k → 10M samples).

The "10M-sample v3 ResMLP" is treated as the canonical / best production model

================================================================================
1. ROBOT AND PROBLEM SETUP
================================================================================

Robot model
-----------
  Robot         : Universal Robots UR5e (6-DOF revolute)
  Kinematics    : Product-of-Exponentials (PoE) formulation
  Link params   : L1 = 425.0 mm, L2 = 392.2 mm
                  H1 = 162.5 mm, H2 =  99.7 mm
                  W1 = 133.3 mm, W2 = 259.6 mm
  Max reach     : ~850 mm
  Joint limits  : q_i in [-pi, +pi] for all i
  FK source     : utils.build_ur5e_model()  →  (w_i, v_i, M) screw axes

Problem
-------
Given a desired end-effector transform T_target in SE(3), find joint angles
q = [q1,...,q6] such that FK(q) = T_target. The UR5e has up to 8 IK branches
and Jacobian singularities, so purely numerical solvers (Newton-Raphson, LM)
are brittle with respect to initialization. The project's hypothesis is:

    A DNN trained on FK-generated (pose, seed-joints) → (joints) data can
    produce an initial joint estimate that lands inside the convergence basin
    of a damped Newton-Raphson solver, making the hybrid system both faster
    and more reliable than random initialization.

2. DATA GENERATION
================================================================================

2.1  Dataset versions
----------------------

Three generations of datasets exist in the repo:

  v1 datasets (pose-only, unconditioned)
    Script : generate_pose_dataset.py / generate_ur5e_fk_ik_dataset.py
    Input  : 12D full pose [x,y,z, r11..r33]  (or 9D [xyz + 6D rotation])
    Output : 12D sin/cos of joints
    Files  : ur5e_pose_dataset.csv, ur5e_ik_dataset.csv, my_data.csv

  v2 datasets (region-conditioned MoE experiments)
    Script : ik_v2/generate_region_dataset.py
    Input  : pose + scalar region-ID (workspace partition)
    File   : ik_v2/ur5e_region_dataset.csv
    Status : exploratory only

  v3 datasets (seed-conditioned — PRODUCTION)
    Script : ik_v3/generate_dataset.py
    Input  : 9D pose (3D position + 6D continuous rotation)
             + 6D seed-joint vector (a perturbed version of ground truth)
    Output : 12D sin/cos of ground-truth joints
    Files  : ik_v3/ur5e_seed_10m.csv        ≈ 1.43 GB, 10,000,000 rows (BEST)
             ik_v3/ur5e_seed_dataset.csv    ≈ 225  MB,  1,000,000 rows
             ur5e_seed_500k.csv, ur5e_seed_200k.csv,
             ur5e_seed_100k.csv, ur5e_seed_50k.csv, ur5e_seed_10k.csv
                                            (smaller scaling slices)

2.2  Generation algorithm (v3)
------------------------------
For each of the N target samples the generator runs:

  1. Sample ground-truth joints q* ~ Uniform(-pi, +pi)^6.
  2. Compute T = FK(q*) via a vectorised PoE (loop over 6 joints, not N
     samples → ~100× faster than per-sample). See _fk_batch() in
     ik_v3/generate_dataset.py.
  3. Extract the 9D pose from T:
         pose_9d = [x, y, z, r11, r21, r31, r12, r22, r32]
     (6D rotation representation of Zhou et al., 2019 — drops the third
     column of R to avoid SO(3) discontinuities.)
  4. Generate a "current-state" seed:
         q_seed = clip(q* + N(0, sigma=0.5 rad), limits)
     The 0.5-rad jitter models a realistic controller state near q*.
  5. Encode the ground-truth joints as sin/cos pairs (12D).
  6. Write row: [pose_9d, seed_6d, q1..q6].

2.3  Representation choices (ik_v3/representations.py)
-------------------------------------------------------
  * 6D rotation  — Gram-Schmidt-decodable, no gimbal lock, smooth for NNs.
  * sin/cos joints — removes the +/-pi wraparound discontinuity; at inference
    the predicted pairs are L2-normalised then atan2-decoded.
  * Pose and seed inputs are scaled with INDEPENDENT StandardScalers fit
    only on the train split, then concatenated to a 15D network input.


================================================================================
3. MODEL ARCHITECTURE EVOLUTION
================================================================================

3.1  v1 — flat MLP / ResMLP on raw pose (model.py, train_ik_model.py)
---------------------------------------------------------------------
  Input  : 12D full pose (no seed).
  Output : 12D sin/cos.
  Variants tested (see results/ tree):
      mlp_3x128, mlp_3x256, mlp_4x256, mlp_5x256,
      resmlp_2x128, resmlp_4x256
  Activation : GELU  Norm : LayerNorm.
  Outcome : all variants plateau at MAE ~1.0 rad (~58°) and ~330-400 mm
  Cartesian error regardless of width/depth. The model cannot disambiguate
  IK branches from pose alone — this motivated v3.

3.2  v2 — region/expert/MoE experiments (ik_v2/)
------------------------------------------------
  * model_global.py    — stronger global residual MLP (SiLU, LayerNorm).
  * model_expert.py    — one specialist per pre-computed workspace region.
  * model_moe.py       — Mixture-of-Experts with soft / top-k gating.
  * model_refinement.py — iterative DeltaNet refinement:
                          q_{t+1} = q_t + DeltaNet(pose, q_t).
  Outcome : region-partitioning did help local experts locally but did NOT
  beat a single seed-conditioned network on global error, and training was
  substantially more complex. Dropped.

3.3  v3 — seed-conditioned ResMLP (ik_v3/model.py) — PRODUCTION
---------------------------------------------------------------
  Input   : 15D = 9D pose + 6D seed joints (both standardised).
  Output  : 12D sin/cos of ground-truth joints.
  Params  : 535,820 trainable.
  Layers  : 15 → 256 → 512 → 512 → 256 → 12
            (BatchNorm + Mish after every linear)
            Residual skip (512→512) inside block 3.
            Residual skip from block-1 output (256) into block-4 output.
  Why this won:
    * The seed input breaks the multi-modality of IK — the network learns
      the *local* branch closest to the current config.
    * Mish + BatchNorm trained far more stably than GELU + LayerNorm.
    * Skip connections across matching widths help gradient flow without
      ballooning parameter count.


================================================================================
4. TRAINING METHODOLOGY (v3)
================================================================================

Script        : ik_v3/train.py
Split         : 80 / 10 / 10  (train / val / test), seeded (random_state).
Loss          : NormalizedSinCosLoss
                  = MSE( L2-normalise-each-(sin,cos)-pair(pred), target )
                Forces predictions onto the unit circle BEFORE MSE so the
                model cannot cheat with impossible trig values.
Optimiser     : Adam, lr = 1e-3.
Scheduler     : ReduceLROnPlateau (factor 0.5, patience 5, min_lr 1e-6).
Batch size    : 2,048.
Epochs        : up to 150 (early stop, patience 20).
Grad clipping : max-norm 1.0.
Scaling       : StandardScaler on pose, StandardScaler on seed (fit on train).
Hardware      : CPU only (no GPU).

Training command (canonical):
    python -m ik_v3.train --csv ik_v3/ur5e_seed_10m.csv \
                          --epochs 150 --out_dir ik_v3/results

Observations
------------
  * Val loss scales almost log-linearly: every 10× more data roughly halves
    val MAE, plateauing around 3° once we hit 10M samples.
  * Training loss stays nearly constant (~0.006-0.010) across sizes — the
    gap between train and val loss at small sizes is textbook overfitting;
    it closes at 10M (train 0.0059 vs val 0.0054).
  * Benchmark convergence rate tracks MAE almost linearly: more data → more
    iterative solves that land inside the Newton basin → fewer failures.
  * There is no sign of data-saturation at 10M — further data would likely
    help modestly, but returns are diminishing.

6. PHASE 2 — ARCHITECTURAL ABLATIONS

6.1  Width / depth sweep on the v1 MLP family (results/ tree, 100k pose data)
-----------------------------------------------------------------------------
All six variants trained on the SAME 100k sample pose-only dataset so the
only variable is architecture.

  Variant         Params   Test MAE (rad)  FK pos err (mm)  FK rot err (rad)
  ------------    ------   --------------  ---------------  ----------------
  mlp_3x128       ~34 k    1.063           381.75           1.315
  mlp_3x256       ~135 k   1.054           359.36           1.373
  mlp_4x256       ~202 k   1.052           377.73           1.301
  mlp_5x256       ~269 k   1.056           377.57           1.315
  resmlp_2x128    ~36 k    1.063           374.75           1.350
  resmlp_4x256    ~345 k   1.053           370.42           1.318

  Same sweep at 50k samples shows the same ordering (mlp_4x256 best at
  365.91 mm, all others within 15 mm of each other).

  Takeaway
  --------
  Without the seed input, NO architecture — Plain MLP, ResMLP, shallow, deep,
  narrow, wide — can push Cartesian error below ~360 mm. The loss surface is
  multi-modal (8 IK branches) and scalar MSE averages the branches, forcing
  the net toward a geometric "centroid" that is physically meaningless.
  The architecture is not the bottleneck — the PROBLEM FORMULATION is.

6.2  Alternative architectures tested and dropped
-------------------------------------------------
  * PlainMLP vs ResMLP on the v1 task
      Plain MLP ≥ ResMLP at every depth/width tested → residual skips gave
      no benefit when the task itself is multi-modal.

  * v2 Mixture-of-Experts / region experts
      Local per-region performance improved slightly but global error,
      training complexity, and inference overhead were worse than a single
      seed-conditioned ResMLP. Not carried forward.

  * v2 iterative refinement (DeltaNet)
      Second-stage delta-prediction reduced residual error on the v2
      pipeline but was redundant once the Newton-Raphson polish stage was
      added at inference time (Section 8).

6.3  Differentiable-FK composite loss (fk_loss_experiments/, 1M data)
---------------------------------------------------------------------
File     : train_ik_model_fk_loss.py  (+ utils_torch_fk.py, model_fk_loss.py)
Script   : run_fk_study.py (sweeps lambda_pos).
Loss     :  L = MSE_sincos + lambda_pos * MSE_xyz( FK_torch(decoded_q), target_xyz )
            where FK_torch is a batched, fully differentiable PoE implemented
            with torch.bmm / torch.cross so gradients flow all the way from
            Cartesian position back through the sin/cos decode to the network.

Results (ablation_summary.csv, same v1-style flat MLP, 1M samples):

  lambda_pos   Val loss   MAE (rad)   FK pos err (mm)   FK rot err (rad)
  ----------   --------   ---------   ---------------   ----------------
  0.00         0.3573     1.0047      334.07            1.068
  0.01         0.3574     1.0042      316.27            1.061
  0.10         0.3587     1.0072      233.80            1.072
  1.00         0.3701     1.0389      117.58            1.223

  Takeaway
  --------
  The composite loss cut Cartesian position error nearly 3× (334 → 118 mm)
  with lambda_pos = 1.0 — a genuine, physics-aware improvement over scalar
  sin/cos MSE. Joint MAE rose slightly (the net trades some joint accuracy
  for task-space accuracy), and rotation error does not improve because the
  auxiliary term only penalises position.

  NOTE: this experiment was run on the older flat-MLP / no-seed pipeline to
  keep the comparison clean against the v1 ablation. Integrating the FK-loss
  into the v3 seed-conditioned network is the natural next step but was not
  in scope for this writeup.


================================================================================
7. PHASE 3 — COMPARATIVE ANALYSIS (what improved, what did not)
================================================================================

Improved the system dramatically
--------------------------------
  * Seed conditioning (v3): single biggest win. Turns the problem from
    multi-modal to approximately uni-modal and enables < 5° joint MAE.
  * Data scaling on the v3 architecture: 10k → 10M drove val MAE from
    ~14.4° down to ~3.1° and benchmark convergence from 54.5% → 77%.
  * Pairing DNN init with Newton-Raphson polish (Section 8): guarantees
    sub-millimetre precision whenever the basin is reached (~77% of poses).
  * 6D continuous rotation + sin/cos joint encoding: both eliminated
    representation-induced discontinuities.
  * NormalizedSinCosLoss: L2-normalising sin/cos pairs before MSE stabilised
    training and prevented "unit-circle drift".
  * Differentiable FK composite loss: ~3× reduction in Cartesian error on
    the non-seed v1 pipeline.

Did not help (or hurt)
----------------------
  * Residual skip connections on the v1 pose-only problem — Plain MLPs
    matched or beat ResMLPs of identical size.
  * Depth > 4 hidden layers on the v1 pose-only problem — flat returns.
  * v2 MoE and per-region experts — added complexity, no net gain.
  * v2 iterative refinement — made redundant by numerical polish at inference.

Bug caught during the FK-loss study
-----------------------------------
The first overnight `run_fk_study.py` sweep returned identical metrics for
all lambda_pos values because the `train_model(...)` call inside main() was
missing `lambda_pos=args.lambda_pos`, silently defaulting every run to 0.0.
Fixed in train_ik_model_fk_loss.py — re-running produced the Section 6.3
numbers.

8. INFERENCE PIPELINE (production)
================================================================================

Artifacts : ik_v3/results/{model_best.pt, pose_scaler.pkl, seed_scaler.pkl}
Entry-pt  : ik_v3.infer.IKSolver

Algorithm (ik_v3/infer.py + benchmark_ik2.py):

  Inputs : T_target (4x4 in SE(3)) and q_current (6-vector).

  1. pose_9d   = extract_pose_9d(T_target)               # Python/NumPy
  2. x_pose    = pose_scaler.transform(pose_9d)
     x_seed   = seed_scaler.transform(q_current)
     x_in     = concat([x_pose, x_seed])                  # 15D
  3. sincos   = model(x_in)                               # single fwd pass
     sincos   = normalize_sincos(sincos)                  # L2 per joint pair
     q_hat    = atan2(sin_i, cos_i) for i = 1..6          # 6D joint guess
  4. q*       = Newton-Raphson(q_hat; T_target)           # damped LS polish
                - Spatial Jacobian via PoE screw axes
                - dq = J^T (J J^T + lambda^2 I)^{-1} e,  lambda^2 = 1e-4
                - Clamp |dq_i| ≤ 0.5 rad per step
                - Converge when  ||e_pos|| < 1 mm   AND  ||e_rot|| < 0.573°
                - Max 200 iterations
  5. Return q*  (or FAIL if no convergence).

Typical inference cost on CPU:
  * DNN forward pass   : ~0.5 ms
  * Newton-Raphson     : ~6-10 iterations, ~0.1 ms each
  * Total per solve    : ~1-2 ms

Why this hybrid wins over the alternatives
------------------------------------------
  * vs. Newton-Raphson + random init (best of 5): +78% relative convergence,
    ~5× fewer iterations, branch-aware (stays near q_current).
  * vs. IKFast closed-form: not limited to spherical-wrist kinematics;
    naturally selects the closest solution.
  * vs. pure end-to-end NN IK: DNN alone is only ~3° / ~10-70 mm accurate;
    the Newton polish provides exact precision whenever it converges.
  * vs. TRAC-IK: DNN init could be slotted in as TRAC-IK's first candidate,
    reducing random restart budget.
